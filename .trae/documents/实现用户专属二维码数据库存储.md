# 用户专属二维码存储功能计划

当前前端 localStorage 的方案在跨设备或清除缓存后会失效，且无法做到“每个用户有自己的二维码”。您希望将二维码内容（Base64 或 URL）存储在数据库中，绑定到每个用户。

## 1. 数据库变更 (`database.py`)
*   **修改 `users` 表**：添加一个新列 `qr_code_url` (Text 类型)，用于存储用户的二维码内容（支持 Base64 长字符串）。
*   **更新函数**：
    *   `get_user_settings(user_id)`: 获取用户的设置（包括二维码）。
    *   `update_user_settings(user_id, qr_code_url)`: 更新用户的二维码。

## 2. 后端 API (`server.py`)
*   **新接口 `/api/settings` (GET)**: 在页面加载时调用，返回当前登录用户的设置（如二维码）。
*   **新接口 `/api/settings` (POST)**: 用于上传或更新二维码内容到数据库。

## 3. 前端逻辑 (`index.html`)
*   **加载逻辑**：页面加载时，不再从 localStorage 读取，而是调用 `/api/settings` 获取当前用户的二维码。
*   **上传逻辑**：用户选择图片后，将其转为 Base64 并通过 POST 请求发送给服务器保存。
*   **渲染逻辑**：生成图片或 PDF 时，使用从服务器获取的最新二维码。

## 4. 迁移与兼容
*   现有的 `users` 表需要通过 `ALTER TABLE` 语句动态添加列，以确保不破坏现有数据。
