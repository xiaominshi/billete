您反馈的“Raw Code（原始代码）不保存，但翻译结果文本能保存”的问题，其根本原因在于 **Raw Code 解析后的数据中残留了特殊字符（如空字符 `\x00`），导致数据库写入崩溃**。

### 原因分析
1.  **Raw Code 包含“脏”字符**：原始 GDS 代码（尤其是复制自终端的）经常包含不可见的二进制字符（如 Null Byte `\x00`）。
2.  **清理不彻底**：
    *   目前的 `server.py` 虽然清理了 `code` 字段（`safe_code = code.replace('\x00', '')`），但**没有清理生成的 `result_text`、`pax_info` 和 `route_info`**。
    *   如果 `logic.py` 解析 Raw Code 时，把这些脏字符带到了乘客名或结果文本里，那么在写入数据库时，数据库驱动（特别是 SQLite/Postgres）会直接报错拒绝写入。
3.  **翻译文本能保存的原因**：您手动粘贴的“翻译结果”是纯净的文本，不含这些二进制脏字符，所以能正常保存。

### 修复方案
我们需要在 `server.py` 保存历史记录之前，对**所有**要存入数据库的字段进行一次彻底的“消毒”，移除所有 `\x00` 字符。

### 执行步骤
1.  **修改 `server.py`**：在调用 `save_to_history` 之前，对 `result_text`、`pax_info`、`route_info` 进行全量清洗。
2.  **重启服务**：验证 Raw Code 是否能正常保存。
