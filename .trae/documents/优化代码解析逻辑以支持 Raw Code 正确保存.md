您反馈的问题（Raw Code 翻译不保存，但 Text 能保存）的根本原因在于：**代码中对“Raw Code”的特殊处理逻辑存在缺陷**。

### 原因分析
1.  **强行合并逻辑 (Line Merging)**：
    *   在 `logic.py` 中，有一个函数 `merge_lines_without_sequence_number`，它的初衷是把 GDS 系统中因为太长而换行的 SSR 信息合并回去。
    *   它的逻辑是：“如果一行不是以数字开头，就把它合并到上一行”。
    *   **问题**：您提供的 Raw Code 虽然有序号，但可能因为格式不标准（例如空格位置不同），导致该逻辑误判，把所有行合并成了一行乱码。这就导致后续解析乘客和航班完全失败，生成了空的结构化数据。
2.  **数据为空导致保存异常**：
    *   因为解析失败，`structured_data` 为空。
    *   `server.py` 在保存历史记录时，会尝试从 `structured_data` 中提取乘客和航线信息。提取不到时，它可能会生成类似 `Unknown Pax` 的占位符，或者因为之前的数据库去重/清洗逻辑（NULL 字符）问题导致在某些环节被拦截。

### 修复方案
我将优化 `logic.py` 中的行处理逻辑，使其更智能，不再“无脑合并”所有非数字开头的行。

### 执行步骤
1.  **修改 `logic.py`**：优化 `merge_lines_without_sequence_number`，增加对航班行特征的判断，避免错误合并。
2.  **重启服务**：验证修复。
