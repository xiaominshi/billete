经过深度排查，您反馈的“手动翻译不保存”问题，其核心原因在于**服务器端代码的健壮性不足，导致在处理特定输入或异常情况时，保存流程被中断或静默失败**。

### 原因总结
1.  **输入处理脆弱**：`server.py` 在接收前端传递的行李参数时，直接使用 `int()` 转换。如果前端传了空值或非数字，程序会直接报错崩溃，根本走不到保存那一步。
2.  **异常静默失败**：如果翻译逻辑（`process`）返回了异常结果，或者数据库因为字段为空（`NULL`）拒绝写入，现有的代码只是打印了日志，没有向前端反馈错误，导致您以为“没反应”。
3.  **空值处理缺失**：数据库某些字段可能不支持 `NULL`，但代码在传递参数时没有做空值转换（例如 `data_json` 为 None 时可能导致写入失败）。

### 修复方案
我将对 `server.py`、`logic.py` 和 `database.py` 进行全链路加固：

1.  **Server 端 (`server.py`)**：
    *   增加 `safe_int` 函数，防止因参数转换错误导致崩溃。
    *   增加对翻译结果的安全解包判断，防止因解析失败导致的崩溃。
    *   在保存前确保 `data_json` 默认通过空 JSON `{}` 填充，而非 `None`。

2.  **Logic 端 (`logic.py`)**：
    *   在调用数据库前，强制将所有可能为 `None` 的参数转换为空字符串或默认值。

3.  **Database 端 (`database.py`)**：
    *   在执行 SQL 前，统一清洗参数，确保没有 `None` 值进入 `TEXT` 类型的字段，彻底消除数据库层面的写入阻碍。
